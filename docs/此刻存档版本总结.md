# 此刻存档 · 版本总结（网页验证版）

> 更新日期：2026-10-09
> 正式网址：https://cike-cundang.pages.dev
> 状态：任务 01–36、38、39 已完成并在 iPhone 上验收；任务 37（30 天验证）进行中。
> 详细规则见 `此刻存档需求文档.md`，实现细节和坑见 `此刻存档技术文档.md`，任务进度见 `此刻存档任务清单.md`。

## 1. 这个版本做了哪些功能

**存档**
- 打开就是存档页，文字（最多 200 字）、照片（最多 10 张，拍照或相册）、语音（最长 1 分钟）至少一项、可以组合。
- 保存后提示“已存档 · 存档点 #N”并跳到时间线；保存失败提示重试，内容不丢。
- 照片处理中、录音中，保存按钮变灰；多张照片里个别读不了的跳过，其余照常添加。
- 草稿：切到别的页面再回来还在（App 被关掉后不保留）。

**撤回与修改**
- 保存后 6 小时内可以“放弃这个存档”或“编辑存档”（文字、照片、语音都能增删换），满 6 小时显示“存档已封存”。
- 手机时间调到存档之前也按已锁定处理；编辑有改动点“取消”会先确认。

**回看**
- 时间线：按日期分组，能看文字、缩略图、大图，能播放语音。
- 365 格子：从第一次存档那天算起，有存档的日子点亮，点亮的格子跳到时间线那一天；满 365 天后继续延长。
- 编号“存档点 #N”连续无空号，撤回后后面的自动往前补位。

**数据与备份**
- 数据只存在这台 iPhone 的浏览器里，不需要账号。
- “备份存档”：生成一个网页文件，通过分享面板“存储到‘文件’”；这个文件不依赖本产品，双击就能看全部存档、听语音。
- “读取存档”：用备份文件全部覆盖当前存档，覆盖前确认，并可“先备份当前存档”。
- 存完一条后，满 7 天没备份会弹窗提醒（“现在备份”/“稍后”）。

**在 iPhone 上用起来**
- 可“添加到主屏幕”，像 App 一样全屏打开（网页清单 `public/manifest.webmanifest`）。
- 打开过一次后，没网也能打开、存档（离线缓存 `public/sw.js`）。
- 在 Safari 里打开时提醒“存档和主屏幕图标里的是分开的”；设置页说明删除图标会删掉存档；显示“持久保存”状态。

**界面**：只用黑白，跟随深色 / 浅色模式，系统默认字体。

## 2. 已知限制和还没做完的部分

**还没做完**
- **30 天验证（任务 37）**：进行中。结束时看格子前 30 格是否至少点亮 20 格，并写 3 句话结论，决定是否做 iOS 版。

**iPhone 系统限制，代码改不了**
- **分享面板无法知道选了哪一项**：选了“微信”“拷贝”等也会记成已备份，提醒可能因此不再出现。每次备份后看清提示，确认选的是“存储到‘文件’”。（技术文档坑 15）
- **麦克风权限可能每次打开都要重新允许**。（坑 16）
- **数据可能被系统清理**：长时间不打开、或删掉主屏幕图标，存档会丢。已申请“持久保存”并加了备份提醒，但只有备份文件才是真正的保险。（坑 2）
- **Safari 和主屏幕图标是两个仓库**，数据不互通。（坑 2）

**有意不处理的（验证版够用）**
- **6 小时锁定靠手机时间**：把时间往回调、但仍在存档时间之后，存档会重新可编辑。（坑 7）
- **备份是一个大文件**：存档多了文件会很大，超过 100 MB 只提示不拦截。（坑 8）
- **跨时区**：按手机当前时区显示日期，出差时同一条存档的日期可能变。（坑 5）
- **部署后更新可能晚一步**：要把 App 划掉重开一两次才是新版。（坑 17）
- **没有专门的 App 图标**：主屏幕图标是 iPhone 自动截的页面图。
- 时间线和视觉风格只做到够用；第 6 节“先不做”的内容（账号、云同步、分享、合并导入、一年前的今天等）都没做。

## 3. 怎么运行这个项目

**第一次准备**（需要 Node.js 22 或更新版本；换到新电脑的详细步骤见 `此刻存档使用教程.md`）

```bash
cd ~/Desktop/此刻存档
npm install
```

**常用命令**

| 想做什么 | 命令 | 说明 |
| --- | --- | --- |
| 本地开发 | `npm run dev` | 打开 http://localhost:5173 ，改代码页面自动刷新；设置页底部有“仅本地开发可见”的测试工具（生成 300 条测试存档 / 清空） |
| 跑测试 | `npm test` | 规则、数据库、备份格式、文案共 95 个测试，应全部通过 |
| 打包检查 | `npm run build` | 类型检查 + 打包到 `dist/`，有报错就不能部署 |
| 预览正式版 | `npm run build` 后 `npm run preview` | 打开 http://localhost:4173 ，和线上一样（含离线缓存） |
| 发布上线 | `npm run deploy` | 打包并上传到 Cloudflare Pages；第一次要先 `npx wrangler login` 登录 |

**发布后在 iPhone 上**：从主屏幕图标打开，划掉重开一两次，确认是新版。

**注意**：
- 本地 `localhost` 里的存档和线上的是两个仓库，互不影响（坑 1）。
- 部署时终端显示的带随机前缀的网址（如 `https://e7e62c1f.cike-cundang.pages.dev`）也是另一个仓库，不要在那里真实使用。
- 手机访问电脑的 `http://192.168.x.x` 时录音用不了，手机测试一律用正式网址（坑 3）。

## 4. 以后接着改，需要特别注意的地方

### 4.1 碰了就可能丢数据的

| 地方 | 要注意什么 |
| --- | --- |
| 正式网址 | **永远不要换**。换网址等于换仓库，旧存档全部看不到。必须换时先备份，到新网址“读取存档”（坑 1） |
| `src/db/db.ts` 表结构 | 加字段、改字段、加索引，都要新增 `db.version(2)` 并写迁移，不要改 `version(1)`；改之前先备份（坑 6） |
| 备份格式 `src/backup/format.ts` | 改格式要把 `FORMAT_VERSION` 加 1，并保证旧版备份还能导入 |
| 导入 `ImportBackup.tsx` / `replaceAllData` | 顺序必须是“先读、先检查、用户确认，再清空写入”，且在同一个事务里（坑 11） |
| `public/manifest.webmanifest` | 改了以后要删掉主屏幕图标重新添加才生效，而删图标会删存档，先备份（坑 13） |

### 4.2 iPhone 上才会出问题、电脑上看不出来的

- **取照片和语音只能用 `getMediaOfSave`**（`src/db/saves.ts`），不要写 `db.media.where('saveId')`：电脑上正常，iPhone 上照片会空白（坑 14）。
- **离线缓存 `public/sw.js`**：
  - 改了缓存逻辑，要把 `CACHE = 'cike-v2'` 里的版本号加 1，旧缓存才会被清掉；
  - 安装时必须把页面用到的脚本、样式一次存齐，否则 iPhone 离线时白屏（2026-10-09 真机遇到）；
  - 本地 `npm run dev` 不启用离线缓存，要测离线请用 `npm run preview` 或真机。
- **分享面板必须在用户点击后立刻打开**：`saveBackupFile` 里 `navigator.share` 之前不能有 `await`，否则 iPhone 会拒绝打开。
- 真机才遇到的问题，修完一定要在 iPhone 上再验一次；电脑上通过不代表手机上通过。

### 4.3 写代码的约定（`.cursor/rules/project.mdc`）

- **纯前端**：不加后端、服务器、登录、云同步。让 AI 改代码时它可能“好心”加，要拦住（坑 12）。
- **编号不存进数据库**，每次按保存时间现场算（`src/rules/numbering.ts`，坑 4）。
- **“这是哪一天”只用 `src/rules/date.ts`**，不要在别处自己切日期（坑 5）。
- **规则写成纯函数放在 `src/rules/` 并配测试**：编号、锁定、内容检查、格子、备份提醒。
- **文案按需求文档 5.5 的文案表**；`src/test/copy.test.ts` 会逐字检查，改文案要同时改需求文档和测试。
- 界面只用黑白、系统字体，不专门适配电脑。

### 4.4 临时方案，做 iOS 版时要替换

网页版代码**不会复用**到 iOS 版，下面这些都是为了“在网页里凑合能用”，iOS 原生版应直接换成系统能力：

| 网页版的临时方案 | iOS 版应该怎么做 |
| --- | --- |
| IndexedDB 存数据，可能被系统清理 | 用 App 自己的本地存储，不会被清 |
| 备份 = 一个装着全部照片语音的大网页文件 | 用系统的文件导出 / iCloud 备份，可按条或打包 |
| 分享面板无法确认是否真的存进了“文件” | 原生文件导出可以确认结果 |
| 麦克风权限可能每次都问 | 原生 App 一次授权长期有效 |
| 主屏幕网页 + 离线缓存 + Safari 提醒 | 不需要，原生 App 本身就离线可用 |
| 锁定靠手机时间 | 可以考虑用系统可信时间 |
| 主屏幕图标是自动截图 | 设计正式图标 |

能带到 iOS 版的：需求规则（需求文档）、数据结构（技术文档第 3 节）、计算规则（技术文档 2.4、`src/rules/` 及其测试用例），以及 30 天验证的结论。

### 4.5 测试小提示

- `npm test` 只覆盖规则和数据层，**不覆盖页面操作**。改了页面后，至少按任务清单里任务 36、39 的验收步骤，在 iPhone 上手动走一遍核心路径（存档 → 时间线 → 格子 → 编辑 → 放弃 → 备份 → 读取）。
- 在电脑浏览器里模拟“保存失败”等异常，可以临时改写 `IDBObjectStore.prototype.add` 等方法，测完刷新页面即可恢复。
